Detailed Description

Per-operation latency, throughput and allocation benchmark for the std::map Orderbook.

  1. Generate: a seeded synthetic order flow is run once against a book; every call (prefill, warm-up, measured) is recorded with its outcome, so later passes replay identical work.
  2. For each repetition, on a fresh book:
    • latency pass: replay prefill and warm-up untimed, then time every measured call separately and count the allocations it makes;
    • throughput pass: replay again and time the measured calls as one block.

Operations are classified by outcome: add (rests, no trade), match (at least one trade, split by order type), reject (Fill-and-Kill / Fill-or-Kill / Market with no trade) and cancel. Output: CSV files in –out (see bench/RESULTS.md for the columns).
